## Ways to contribute

- **Report a bug.** Use the bug report template and include your WordPress, WooCommerce, PHP and Bagisto versions, the entity type being synced, and the relevant excerpt from **WC to Bagisto → Logs**. Redact tokens, customer names and e-mail addresses first.
- **Propose a feature.** Open an issue describing the problem before writing code, so we can agree on the approach.
- **Improve documentation.** Corrections to `README.md`, `readme.txt` or this file are very welcome.
- **Submit a fix.** Please open or reference an issue for anything larger than a typo.

## Development environment

You need:

| Tool | Version | Why |
| --- | --- | --- |
| PHP | 7.4 – 8.4 | Matches the plugin's supported range |
| WordPress | 6.5+ | Minimum supported version |
| WooCommerce | 9.0+ | Hard dependency (`Requires Plugins: woocommerce`) |
| Node.js | 18+ (20 LTS recommended) | Front-end build |
| npm | 8+ | `package-lock.json` is `lockfileVersion: 3` |
| Composer | 2.x | PHP linting and coding standards (dev only — the plugin has no PHP runtime dependencies) |
| A Bagisto store | Admin REST API reachable, with a Personal Access Token | Nothing can be sync-tested without one |

### Setup

```bash
git clone https://github.com/bagisto/woocommerce-connector.git bagisto-sync-for-woocommerce
cd bagisto-sync-for-woocommerce

# Front-end build toolchain
npm install

# PHP linting / coding standards (dev only)
composer install
```

Symlink or copy the directory into `wp-content/plugins/` of a WordPress install. Use `bagisto-sync-for-woocommerce` as the directory name — that is the plugin slug and text domain.

> The plugin has **no PHP runtime dependencies** and ships no `vendor/` directory. `composer.json` exists purely for the linting toolchain. The background queue extends `WP_Background_Process`, which is provided by the copy WooCommerce bundles at `woocommerce/includes/libraries/wp-background-process.php`.

| `composer check` | `lint` + `phpcs` |

## Coding standards

PHP follows the **WordPress Coding Standards**, enforced by `phpcs.xml.dist`:

- One class per file, filenames `class-<lowercased-class-name-with-dashes>.php`.
- Namespaces under `WKWCBAGCONNECTOR\…`, resolved by the custom autoloader in `includes/autoload.php`. The autoloader derives the file path from the namespace, so **file and directory names must match the namespace exactly**.
- Every global function, constant, option, hook and meta key is prefixed with `wkwctobag_` / `WKWCTOBAG_` / `WKWCBAGCONNECTOR`.
- Tabs for indentation, Yoda conditions, and a docblock on every class, method and function.
- Escape on output (`esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`), sanitise on input, and use `wp_unslash()` on superglobals.

### Security requirements for new code

Any new admin endpoint **must** have both of these, in this order:

```php
// 1. Verify the request came from our UI.
if ( ! wp_verify_nonce( $nonce, 'wkwctobag_admin_ajax_nonce' ) ) {
	throw new \Exception( esc_html__( 'Security check failed.', 'bagisto-sync-for-woocommerce' ) );
}

// 2. Verify the current user is allowed to do this.
if ( ! current_user_can( 'manage_woocommerce' ) ) {
	throw new \Exception( esc_html__( 'You do not have permission to perform this action.', 'bagisto-sync-for-woocommerce' ) );
}
```

Also:

- **Never** register a `wp_ajax_nopriv_` handler for an endpoint that reads or writes store data.
- **Never** set `'sslverify' => false` on an outbound request, and never add `https_ssl_verify` → `__return_false`.
- Use `wp_json_encode()`, not `json_encode()`.
- Do not echo filesystem paths, tokens, or raw API responses to the browser.
- Nonce-protect state-changing `GET` links with `wp_nonce_url()`.

JavaScript lives in `src/js/` and is transpiled by Babel with the WordPress preset. Keep it framework-free — the admin bundle deliberately depends only on jQuery and Select2.

### Coding standards are clean and enforced

`composer phpcs` reports **0 errors and 0 warnings**, and the `coding-standards`
CI job is **blocking**. Run it before you open a pull request:

```bash
composer check   # parallel-lint + phpcs
```

A small number of deliberate deviations are recorded explicitly rather than
silently ignored, so that each one is reviewable:

| Deviation | Where | Why |
| --- | --- | --- |
| `urlencode()` over `rawurlencode()` | `phpcs.xml.dist` (sniff muted, with a rationale and a "revisit" note) | Switching changes how a space is encoded on the wire (`+` → `%20`) in Bagisto API query strings. It needs testing against a live Bagisto instance before it is made. |
| Empty `catch` blocks | 6 inline `phpcs:ignore` annotations | Deliberate best-effort paths; each annotation says what happens instead. |
| Unused function parameters | 6 inline `phpcs:ignore` annotations | The signatures are fixed by the WordPress/WooCommerce hooks the methods are registered against. |
| Direct `file_put_contents()` / `file_get_contents()` | 4 inline `phpcs:ignore` annotations | The logger runs before `WP_Filesystem` is available and must never prompt for credentials. |
| `current_time( 'timestamp' )` | 1 inline `phpcs:ignore` annotation | Log retention must compare against the site-timezone stamps written into the log lines. |
| 5-minute cron interval | 1 inline `phpcs:ignore` annotation | The background-queue health check is intentionally frequent. |

**If you add a `phpcs:ignore`, always include a `--` reason.** An annotation
without a justification will be sent back in review.

There are no security-sniff findings: `WordPress.Security.EscapeOutput`,
`WordPress.Security.NonceVerification`, `WordPress.Security.ValidatedSanitizedInput`
and `WordPress.DB.PreparedSQL` all report zero.

## Internationalisation

- Wrap every user-facing string in a gettext call with the `bagisto-sync-for-woocommerce` text domain.
- Add a `/* translators: … */` comment above any string with placeholders.
- Run `npm run i18n:check` before submitting; it fails on a wrong or missing text domain.
- If you add or change strings, run `npm run i18n` and commit the regenerated `.pot`.
- Strings rendered from JavaScript should be passed through `wp_localize_script()` (see the `i18n` key in `wkwctobagAdminObj`) rather than hardcoded in `src/js/`.

## Committing built assets

`assets/js/admin.js` and `assets/css/admin.css` are **generated files that are intentionally tracked in git**. WordPress plugins are distributed as ready-to-run directories, so the built assets must be present in a clone, a GitHub source archive and the WordPress.org package.

Because of that:

- If you change anything under `src/`, run `npm run buildr` and commit the regenerated assets **in the same commit**.
- If your change touches only PHP, docs or configuration, do **not** rebuild — an unrelated toolchain-version diff in the bundle makes review harder.
- Never edit the generated files directly.

## Testing your change

The project has no automated test suite yet (see [Project status and known limitations](README.md#project-status-and-known-limitations)). Until it does, please verify manually and say what you did in the pull request:

1. `composer check` passes.
2. `npm run i18n:check` passes.
3. `npm run buildr` completes if you touched `src/`.
4. Connect to a Bagisto instance, then exercise the affected path — for example run the relevant bulk sync, confirm the record appears in Bagisto, and confirm **WC to Bagisto → Logs** shows no new errors.
5. Confirm you have not changed behaviour for existing installs (settings, option names, meta keys and hook names are a public contract).

Please state the versions you tested against: WordPress, WooCommerce, PHP and Bagisto.

## Pull request checklist

- [ ] Branched from `main`, and the branch does one thing.
- [ ] `composer check` and `npm run i18n:check` pass.
- [ ] Built assets rebuilt and committed **only if** `src/` changed.
- [ ] No new `sslverify => false`, no new `wp_ajax_nopriv_` handler, no unguarded endpoint.
- [ ] No secrets, tokens, customer data, log files, database dumps or `node_modules/` in the diff.
- [ ] Existing option names, meta keys, hook names and filter signatures unchanged, or the break is called out explicitly.
- [ ] `CHANGELOG.md` updated under `## [Unreleased]`.
- [ ] Manual test steps and version matrix described in the PR body.
